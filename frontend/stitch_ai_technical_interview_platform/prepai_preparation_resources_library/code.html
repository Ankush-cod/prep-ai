THREE EASY PIECES: CONCURRENCY SEC 28.3
Chapter 28

Locks and Hardware Primitives

From the previous chapters, we saw that concurrency introduces race conditions: multiple threads of execution accessing shared mutable state without synchronization can produce nondeterministic errors. We now introduce the most fundamental mutual exclusion primitive: the lock.

The Crux: How to Build a Spinlock?

How can hardware support lock operations efficiently? What instructions must the processor expose so that software can guarantee mutual exclusion without deadlocking or starving threads?

test_and_set.c (x86_64 Primitive) Atomic Instruction 
int TestAndSet(int *old_ptr, int new_val) {
    int old = *old_ptr; // fetch old value
    *old_ptr = new_val; // store new value
    return old;         // return old value
}

void lock(lock_t *lock) {
    while (TestAndSet(&lock->flag, 1) == 1)
        ; // spin-wait (relinquish or pause)
}

Because this operation happens atomically via CPU cache coherency busses, no two threads can simultaneously receive 0 from the test-and-set invocation. Only one thread succeeds in entering the critical section.
